# Examples (synthetic only)

Everything in this directory was generated by GEODESIC from its bundled
**synthetic** fixtures (an inert tracer moving through engineered reservoirs).
None of it is research evidence, and no real project data may be placed here.

`synthetic_demo/` is the output of one run of the offline demonstration:

    geodesic demo --dir <demo directory>

| Path | What it is |
|---|---|
| `synthetic_demo/demo_output.txt` | Console output of that run (the demo directory is shown as `<demo directory>`). |
| `synthetic_demo/inputs/` | The generated input files: fixture workbook (two versions), workbook profile and starter mapping, the confirmed fixture mapping, fixture search responses, a fixture RIS export, a fixture PDF, the project configuration and the fixture protocol. |
| `synthetic_demo/report/` | The report directory written at the end of the demo: self-contained HTML report, figures (SVG, PDF, PNG at 300 DPI), tables (Excel, CSV, JSON, RIS) and the manifest. Every file name starts with `SYNTHETIC_`. |

`scale_test/SYNTHETIC_scale_report.json` is the report written by the full-size
scale smoke test (`python -m pytest tests -m scale -s`) on 2026-11-09: the
requested size, the environment, the counts reached and the measured time of
each step. The numbers are observations from one run on one machine; see
`docs/TESTING.md`.

Review actions in the demo are **simulated** (performed by actors of kind
`simulated`, which exist only in synthetic projects) and are recorded and
exported as such. Identifiers and timestamps differ on every run, so a new run
does not reproduce these files byte for byte; the counts are the same.

The project database of the demo run is not distributed. Run the command above
to create one, then look at it with `geodesic dashboard --project <demo directory>/project`.
